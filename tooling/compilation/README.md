# C Compilation & Linking Lab

A hands-on exploration of the C build pipeline, object files, symbol resolution, ARM64 assembly, and compiler optimizations.

**Environment:** macOS (Apple Silicon / ARM64), Apple Clang, Mach-O.

## 1. Compilation Pipeline

```text
Source (.c) → Preprocessing (.i) → Assembly (.s) → Object (.o) → Executable
```

| Command | Purpose |
|---|---|
| `clang -E main.c -o main.i` | Preprocess source (`#include`, macros) |
| `clang -S -O0 main.c -o main.s` | Generate unoptimized ARM64 assembly |
| `clang -S -O2 main.c -o main_optimized.s` | Generate optimized assembly |
| `clang -c main.c -o main.o` | Compile and assemble without linking |
| `clang main.o -o main` | Link the object file into an executable |
| `./main` | Execute the program |
| `file main` | Inspect executable format and architecture |

### Useful Compiler Flags

| Flag | Meaning |
|---|---|
| `-std=c11` | Use the C11 language standard |
| `-Wall -Wextra -Wpedantic` | Enable compiler warnings |
| `-O0` / `-O2` | Disable / enable optimization |
| `-g` | Generate debugging information |
| `-E` / `-S` / `-c` | Stop after preprocessing / assembly generation / object generation |
| `-o` | Specify output filename |

Full debug build:

```bash
clang -std=c11 -Wall -Wextra -Wpedantic -O0 -g main.c -o main
```

## 2. Object Files & Symbol Inspection

```bash
file main.o
nm main.o
```

Example symbols:

```text
T _add
D _counter
T _main
U _printf
```

- `T`: Defined in the text (code) section.
- `D`: Defined in the initialized data section.
- `B`: Defined in zero-initialized storage.
- `U`: Undefined symbol requiring resolution.

**Key concept:** Headers provide declarations, while object files or libraries provide definitions. The linker resolves external references.

## 3. Separate Compilation & Linking

`broken.c` calls `multiply()`; `math_ops.c` contains its implementation.

```bash
# Compile separately
clang -c broken.c -o broken.o
clang -c math_ops.c -o math_ops.o

# Inspect symbols
nm broken.o       # U _multiply
nm math_ops.o     # T _multiply

# Demonstrate a linker error
clang broken.o -o broken

# Resolve the symbol and link successfully
clang broken.o math_ops.o -o multiply_demo

# Run and inspect the exit status
./multiply_demo
echo $?
```

The linker error occurs because `_multiply` has no available definition until `math_ops.o` is included.

## 4. Mach-O Sections & Relocations

```bash
# Inspect sections
otool -l main.o

# Concise section summary
otool -l main.o | grep -E 'sectname|segname|size '

# Inspect relocation records
otool -rv main.o
```

| Section | Contents |
|---|---|
| `__TEXT,__text` | Machine instructions |
| `__DATA,__data` | Initialized global/static variables |
| `__TEXT,__cstring` | String literals |
| `__bss` | Zero-initialized storage, when present |

Common ARM64 relocations:

- `BR26` — PC-relative branch/call.
- `PAGE21` — Symbol page-address calculation.
- `PAGOF12` — Offset within the page.

Relocation records allow the linker to resolve references after arranging code and data.

## 5. ARM64 Assembly & Optimization

Compare the assembly generated by `-O0` and `-O2`.

At `-O2`, the `add()` function can compile to:

```asm
_add:
    add w0, w1, w0
    ret
```

ARM64 calling convention essentials:

- `w0`–`w7`: First integer arguments (32-bit values).
- `w0`: Return register for `int`.
- `x0`–`x7`: Corresponding 64-bit register views.
- `sp`: Stack pointer.
- `x29`: Frame pointer by convention.
- `x30`: Link register.
- `bl`: Function call.
- `ret`: Function return.

Optimizations can eliminate stack usage, inline functions, and remove redundant calculations.

## Key Takeaways

1. Compilation and linking are distinct stages.
2. Object files contain machine code, symbols, sections, and relocations.
3. Undefined symbols are normal in object files but must be resolved during linking.
4. Compiler optimizations can significantly change generated machine code.
5. Understanding the toolchain is essential for debugging low-level software.

**Linux equivalent:** GCC with ELF inspection tools such as `nm`, `readelf`, and `objdump`.
